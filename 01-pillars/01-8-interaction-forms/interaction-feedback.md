# 交互反馈：防抖与节流（Debounce & Throttle）

> 用户在搜索框狂敲、疯狂拖动滑块、连点按钮——这些高频操作如果不控制，会触发海量计算/请求，界面卡死。防抖和节流是控制"触发频率"的两大工具。

## 是什么

防抖和节流都是**限制函数执行频率**的技术，但策略不同：

| 技术 | 策略 | 通俗 |
|---|---|---|
| **防抖（debounce）** | 连续触发时，只执行**最后一次**（停下来才执行） | "等你说完再反应" |
| **节流（throttle）** | 固定**时间间隔**执行一次（期间最多一次） | "按固定频率反应" |

```
用户连续输入 a-p-p-l-e（每 50ms 一个字符）：

防抖（300ms）：                       节流（300ms）：
a 输入 → 重置计时                      a 输入 → 执行（第1次）
p 输入 → 重置计时                      p 输入 → 忽略
p 输入 → 重置计时                      p 输入 → 忽略
l 输入 → 重置计时                      l 输入 → 执行（300ms到）
e 输入 → 重置计时                      e 输入 → 忽略
（停手 300ms 后）→ 执行一次            （继续按 300ms 间隔执行）
```

一句话边界：**防抖要"最终结果"，节流要"过程中也有反馈但别太频"。**

## 为什么：高频操作的危害

回到 [复杂度来源](../../00-foundation/complexity-sources.md) 差异 4——用户行为非结构化、不可预测。用户连点、狂输、猛拖，如果不限制：
- **搜索框**：每输一个字符发一次请求 → 搜索接口被打爆，还出现 [竞态](../01-6-data-fetching/race-cancellation.md)。
- **滚动/拖拽**：每次触发都做重计算 → 主线程被占满，界面卡顿。
- **窗口 resize**：拖动窗口大小连续触发 → 布局反复重算。

防抖节流把这些**降频到合理范围**，既保留响应性又不压垮系统。

## 怎么用：场景匹配

### 防抖适合"只关心最终结果"
| 场景 | 为什么用防抖 |
|---|---|
| 搜索框联想 | 用户输完一个词再搜，不要输一半就搜 |
| 表单异步校验 | 用户输完再查服务端 |
| 自动保存 | 用户停止编辑后再保存，别边输边存 |

```
// 搜索联想：用户停止输入 300ms 后才请求
const handleSearch = debounce(query => fetchSuggestions(query), 300)
<input onChange={e => handleSearch(e.target.value)} />
```

### 节流适合"过程中也要反馈，但别太频"
| 场景 | 为什么用节流 |
|---|---|
| 滚动事件（懒加载、吸顶） | 滚动很频繁，但需要持续反馈位置 |
| 拖拽（实时位置更新） | 要看到拖动过程，但不用每像素都更新 |
| 窗口 resize | 要响应大小变化，但别每次微调都重算 |

```
// 滚动吸顶：每 100ms 最多检查一次滚动位置
window.addEventListener('scroll', throttle(checkSticky, 100))
```

### requestAnimationFrame —— 动画/渲染的节拍 ★
对于需要和屏幕刷新同步的（动画、视觉更新），用 `requestAnimationFrame` 而非节流——它自动对齐浏览器刷新率（通常 60fps），既流畅又不浪费：
```
// 拖拽时更新位置，对齐刷新率
function onDrag(e) {
  requestAnimationFrame(() => updatePosition(e))   // 下一帧再更新，不阻塞
}
```
> rAF 比节流更适合"视觉更新"，因为它精确对齐渲染时机。详见 [01-3 动画](../01-3-styling/animation-transition.md)。

## 常见坑

- ❌ **搜索框不防抖**：每输一个字符请求一次，打爆接口 + 竞态。
  - ✅ 正例：防抖 300-500ms。
- ❌ **混淆防抖和节流**：搜索框用节流（过程中也搜了，浪费）；滚动用防抖（停下才反馈，体验断裂）。
  - ✅ 正例：只要最终结果用防抖；过程要持续反馈用节流。
- ❌ **防抖/节流函数不取消**：组件卸载时定时器还在跑，回调操作已卸载组件。
  - ✅ 正例：卸载时清理（cancel）。
- ❌ **滚动事件不节流就做重计算**：滚动每秒触发几十次，重计算导致卡顿。
