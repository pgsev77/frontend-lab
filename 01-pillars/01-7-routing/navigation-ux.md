# 导航体验（Navigation UX）

> 路由切换不只是"换个组件"，它是一次用户体验事件——有等待、有过渡、有位置记忆。处理不好，用户会感到"卡顿、迷失"。这篇讲导航的体验细节。

## 是什么

导航体验指**用户在路由切换过程中的感受**，包括：加载态、过渡、滚动位置、错误页、返回行为。技术实现之上，它关乎用户对"我在哪、发生了什么"的感知。

一句话边界：**导航体验 = 让用户始终知道"正在发生什么、我在哪里"。**

## 为什么：导航的几个体验痛点

### 痛点 1：切换瞬间的空白
懒加载页面（[代码分割](./code-splitting.md)）或数据路由（[data-routing](./data-routing.md)）加载新页代码/数据时，界面会短暂空白。没有过渡，用户以为"卡死了"或"点错了"。

### 痛点 2：滚动位置丢失
用户在长列表滚到第 50 条，点进详情页，再后退——回到列表顶部，第 50 条没了，要重新滚。这种"位置迷失"很挫败。

### 痛点 3：错误路由无反馈
访问不存在的路径（/typo），只看到空白或服务器 404，用户不知所措。

## 怎么用：四个体验细节

### 1. 导航过渡态（pending state）
路由切换加载数据/代码期间，显示过渡反馈：
- **顶部进度条**（如 NProgress）：一条细线从左滑到右，告诉用户"正在加载"。
- **保留旧页 + 加载指示**：切换时不立即清空，而是旧页之上叠加轻微的加载指示（变灰/Spinner），数据到了再切。
- **骨架屏**：新页的内容区先显示骨架，数据到了填充。

```
点击导航 → [显示进度条/骨架] → 数据&代码就绪 → [平滑切换到新页]
```
> 过渡态的核心是"反馈"——让用户知道"点击生效了，正在处理"。呼应 [01-9 感知性能](../01-9-performance-ux/README.md)。

### 2. 滚动恢复（Scroll Restoration）
后退/前进时，恢复到原来的滚动位置：
```
// React Router 等支持
<Router scrollRestoration="auto"/>   // 自动恢复滚动位置
```
- 长列表后退回到原来位置，用户不迷失。
- 注意：某些场景应滚动到顶部（如进入新页面，应从顶部开始，而非继承上一页位置）。路由库通常支持"新导航滚顶、后退恢复"的策略。

### 3. 404 与错误路由
配置兜底路由，友好处理不存在/出错的情况：
```
<Route path="*" element={<NotFound/>}/>   {/* 匹配所有未定义路径 */}
<Route errorElement={<ErrorBoundary/>}/>  {/* 路由渲染出错时兜底 */}
```
- NotFound 页要友好（建议的链接、回首页按钮），不是冷冰冰的"404"。
- 路由级错误边界捕获渲染错误，显示降级 UI，呼应 [01-13 错误边界](../01-13-observability-quality/README.md)。

### 4. 过渡动画（可选）
路由切换加过渡动画（淡入淡出、滑动），让切换更顺滑。但注意：
- 动画不要太长（>300ms 觉得慢）。
- 用 CSS transition/View Transitions API，别用重排属性。呼应 [01-3 动画](../01-3-styling/animation-transition.md)。

## 常见坑

- ❌ **切换时白屏无反馈**：用户以为卡死。
  - ✅ 正例：进度条/骨架/保留旧页过渡。
- ❌ **后退滚动位置丢失**：长列表后退回顶部，用户要重滚。
  - ✅ 正例：启用 scrollRestoration。
- ❌ **新页面继承上一页滚动位置**：从长文章点进新页，新页停在中间而非顶部。
  - ✅ 正例：新导航滚顶，后退才恢复。
- ❌ **没有 404 兜底**：访问错路径空白或报错。
  - ✅ 正例：友好的 NotFound + 回首页入口。
- ❌ **过渡动画过长**：每次切页都要等动画，反而拖沓。
