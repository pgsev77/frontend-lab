# 层叠与特异性（Cascade & Specificity）

> "为什么我的样式不生效？"——这是前端被问得最多的问题，90% 的答案是：**特异性或层叠**。CSS 不像编程语言"后定义覆盖前定义"，它有一套复杂的"谁赢"规则。理解这套规则，才能从"瞎试 !important"变成"精准定位"。

## 是什么

CSS 的 C 是 **Cascade（层叠）**：当多条规则作用于同一元素同一属性时，浏览器要决定**谁赢**。决定的依据是一套优先级排序，其中最常打架的是**特异性（Specificity）**。

- **层叠（Cascade）**：处理"多条规则冲突"的整体机制。
- **特异性（Specificity）**：衡量一个选择器"有多强"的数值，特异性高的赢。

一句话边界：**层叠是规则，特异性是规则里最常用的评判维度。**

## 为什么：为什么需要这套机制

CSS 设计初衷是"允许多个样式来源叠加"：浏览器默认样式、用户样式、开发者样式、多个 CSS 文件、框架样式、组件库样式……它们都会作用到同一元素。如果没有一套统一的"谁优先"机制，结果就无法预测。

这套机制让 CSS 既灵活（可叠加）又确定（有明确的赢家规则）。但它也带来了复杂度——当样式"不生效"时，你得知道是哪条规则赢了。

## 怎么工作：决定谁赢的优先级（从高到低）

当多个规则冲突，浏览器按这个顺序决定赢家：

1. **`!important`**（最高，慎用）
2. **行内样式**（`style="..."`）
3. **特异性**（选择器权重）★ 最常打交道
4. **源顺序**（特异性相同时，后写的赢）

### 特异性计算（★ 核心）

选择器的特异性用 **(ID数, 类/属性/伪类数, 元素/伪元素数)** 三元组表示：

| 选择器 | ID | 类/属性/伪类 | 元素/伪元素 | 特异性 |
|---|---|---|---|---|
| `*`（通用） | 0 | 0 | 0 | (0,0,0) |
| `li` | 0 | 0 | 1 | (0,0,1) |
| `.nav` | 0 | 1 | 0 | (0,1,0) |
| `#header` | 1 | 0 | 0 | (1,0,0) |
| `ul li` | 0 | 0 | 2 | (0,0,2) |
| `.nav .item` | 0 | 2 | 0 | (0,2,0) |
| `#header .nav li` | 1 | 1 | 1 | (1,1,1) |

**比较规则**：从左到右逐位比，左边大的整体就大。`(1,0,0)` 永远大于 `(0,9,9)`——**一个 ID 选择器比任意多个类选择器都强**。

> 直觉陷阱：很多人以为"越长的选择器越强"，错。10 个类选择器连起来 `(0,10,0)` 也赢不了一个 `#id` `(1,0,0)`。

### 源顺序（平局打破者）
特异性相同时，**后加载/后写的样式赢**。这就是为什么"把样式表放后面""覆盖第三方库时要写在后面"。

### 继承（Inheritance）—— 容易混淆的概念
部分 CSS 属性（如 `color`、`font-size`）会**继承**给子元素；部分（如 `border`、`margin`）不会。继承的优先级**低于任何直接设定的规则**——直接给元素设的样式永远赢过继承来的。

## 常见坑

- ❌ **用 `!important` 强制覆盖**：一旦开始用 important，很快处处 important，最终 important 之间还要比特异性，彻底失控。important 应是最后的手段。
  - ✅ 正例：用更高特异性的选择器覆盖，或调整源顺序。
- ❌ **靠 ID 选择器写样式**：ID 特异性太高 `(1,0,0)`，后续想覆盖几乎只能用 important 或更长的 ID 选择器。组件化开发里应**避免用 ID 写样式**。
  - ✅ 正例：用 class 写样式，ID 只用于锚点/JS 钩子。
- ❌ **不理解"特异性不可越级"**：以为多加几个 class 就能盖过 ID。`(0,5,0)` 仍输给 `(1,0,0)`。
- ❌ **被继承误导**：给父元素设 `border` 以为子元素也会有边框——`border` 不继承。

### 现代 CSS 的解法：层叠层（@layer）
新特性 `@layer` 让你**显式声明样式的层级**，层级低的整体被层级高的覆盖，与特异性无关。这解决了"第三方库样式 vs 自定义样式"打架的难题：
```css
@layer reset, framework, components, utilities;
@layer framework { /* 框架样式，整体低于 components */ }
@layer components { .btn { color: red; } }  /* 即使特异性低也赢 framework */
```
结合原子化 CSS（如 Tailwind 的 utilities 层），可以让样式优先级**可预测、不靠特异性战争**（→ 详见 [01-3 样式方案](../01-3-styling/README.md)）。
