# HTML 语义化（Semantic HTML）

> 这是视图轴的起点。在学组件、框架之前，先理解 HTML 标签不只是"让文字显示出来"，而是承载**语义**——它告诉浏览器、搜索引擎、辅助技术"这块内容是什么"。语义化是 [可访问性](../01-10-accessibility-multiplatform/README.md) 和 SEO 的共同地基。

## 是什么

语义化 HTML（Semantic HTML）指**用恰当的标签表达内容的含义，而非只用 div/span 搞排版**。标签不只是视觉容器，而是带"角色"的语义单元：`<h1>` 是主标题、`<nav>` 是导航、`<main>` 是主体内容、`<button>` 是按钮。

一句话边界：**语义化关注"它是什么"，样式关注"它长什么样"**——两者解耦。一个 `<div>` 加上点击事件能"看起来像按钮"，但它对屏幕阅读器和键盘仍然是"什么都不是"。

## 为什么：语义化解决三个问题

### 问题 1：可访问性（a11y）的基石
屏幕阅读器**靠标签语义**来理解页面结构并朗读给视障用户。看两组等价实现：

```
❌ 反例（全是 div，语义为零）
<div class="header">
  <div class="title">商品列表</div>
  <div class="item" onclick="buy()">手机</div>
</div>
```
```
✅ 正例（语义化）
<header>
  <h1>商品列表</h1>
  <ul>
    <li><button onclick="buy()">手机</button></li>
  </ul>
</header>
```
对屏幕阅读器：左侧是一堆无意义的 div；右侧能读出"标题 1 级 商品列表、列表 1 项、按钮 手机"。<button> 还自带键盘可达（回车/空格触发），div 需要手动补 `role`、`tabindex`、键盘事件——**语义化标签免费送了这些能力**。

### 问题 2：SEO 与可解析性
搜索引擎爬虫靠语义理解页面：哪个是主标题、哪里是正文、哪些是导航。语义清晰，页面才能被正确收录、关键词才能被准确识别。**`<h1>` 的权重高于 `<h2>`，主标题放 `<h1>` 能提升相关搜索排名。** 此外，浏览器自带的"阅读模式"、AI 提取正文，都依赖语义化结构。

### 问题 3：可维护性与默认行为
- **可读性**：看 `<article>` 立刻知道是一篇独立内容，看 `<div class="xxx">` 要点进去猜。
- **默认行为**：`<button>` 自带键盘交互和表单提交、`<a>` 自带链接跳转、`<form>` 自带回车提交。用 div 重造这些，既费事又容易漏掉边界情况（如提交时按回车）。

## 怎么用：文档大纲与语义标签

一个典型页面的语义化骨架：

```
<body>
  <header>            文档或区块的页眉（logo + 导航）
    <nav>             主要导航链接
  </header>
  <main>              页面的主体内容，整个文档唯一
    <article>         可独立分发/复用的独立内容（一篇文章/一个帖子）
      <h1>            文章主标题（每页层级从 h1 起）
      <section>       主题相关的内容分组，通常带标题
        <h2>
      </section>
    </article>
    <aside>           侧边栏、相关推荐、广告（与主体相关性较弱）
  </main>
  <footer>            页脚（版权、联系方式、辅助链接）
</body>
```

### 关键标签的语义辨析
| 标签 | 语义 | 易混淆点 |
|---|---|---|
| `<section>` | 主题相关的内容分组，**通常带标题** | 没有标题的区块用 `<div>` 即可，别滥用 section |
| `<article>` | 可独立存在的完整内容 | 帖子/文章/评论用 article；纯版块用 section |
| `<nav>` | **主要**导航 | 页脚的小链接组不算 nav，用普通列表即可 |
| `<main>` | 页面主体，**每页唯一** | 别把 main 当通用容器，它标识"跳过导航直达正文" |
| `<figure>` / `<figcaption>` | 图表及其标题 | 插图、代码示例、图表都可用 |
| `<time>` | 机器可读的时间 | 利于搜索引擎和日历应用解析 |

### 标题层级（h1-h6）
- 每页应有清晰的标题层级，**不要跳级**（h1 后直接 h3 是错的）。
- 现代 HTML 允许每篇文章（article）有自己的 h1（outline 算法），但实践中"每页一个 h1"最稳妥（兼容性好）。

## 常见坑

- ❌ **div 满天飞**：用 `<div onclick>` 当按钮。屏幕读不出来、键盘用不了、表单提交不了。
  - ✅ 正例：交互元素用 `<button>`/`<a>`，结构用语义标签，**div 只用于无语义的纯样式容器**。
- ❌ **按样式选标签**：因为 `<h2>` 字大就用它，导致标题层级混乱、SEO 权重错乱。
  - ✅ 正例：语义决定标签，**样式用 CSS 控制**（给 h2 设样式，而不是用 h2 来"放大字"）。
- ❌ **滥用 section**：每个区块都套 `<section>` 却不带标题。section 的语义是"带主题的内容分组"，无主题就用 div。
- ❌ **用 `<b>`/`<i>` 凑样式**：它们虽有语义（b=注意、i=不同语态），但常被误当加粗/斜体用。纯视觉加粗用 `<span>` + CSS；真要表达语义用 `<strong>`（重要）/`<em>`（强调）。
