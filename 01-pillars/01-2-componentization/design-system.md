# 设计系统（Design System）

> 当团队变大、产品线变多，"按钮这个圆角是 4px 还是 6px"这种问题会被反复争论。设计系统就是把这些决策**一次性固化**，让全团队的界面保持一致、让复用走到极致。

## 是什么

设计系统（Design System）是一套**统一的视觉语言与组件规则**，通常包含三层：

| 层 | 内容 | 例子 |
|---|---|---|
| **设计令牌（Token）** | 最基础的视觉变量：颜色/间距/字号/圆角/阴影 | `--color-primary: #1677ff` |
| **组件库** | 基于令牌实现的、可复用的 UI 组件 | Button、Input、Modal |
| **规范文档** | 什么时候用什么、怎么组合 | "错误态用 danger 色，不用红" |

一句话边界：**设计系统 = 令牌 + 组件库 + 规范**。组件库是设计系统的代码实现，令牌是组件库的地基。

> 三者关系：令牌（原子）→ 组件（分子）→ 页面（有机体）。改一个令牌，所有用到它的组件自动更新——这是"单一修改点"思想在视觉层面的体现。

## 为什么：设计系统解决什么

### 问题 1：视觉不一致
没有设计系统时，每个页面、每个开发者各自定颜色/间距，结果是"五种主色、八个圆角、十种字号"，产品显得业余。设计系统**把决策收敛为单一来源**（single source of truth）。

### 问题 2：重复造轮子
每个团队都自己写一套按钮、表单、对话框。设计系统让这些**只实现一次、全团队复用**。

### 问题 3：设计与开发脱节
设计师在 Figma 里定的颜色，开发在代码里硬编码，两边慢慢漂移。设计令牌作为**双方共享的单一事实源**，让设计稿和代码用同一套变量。

## 怎么用

### 1. 设计令牌（★ 地基）
令牌是把视觉决策**命名化、变量化**。分三层：
```
全局令牌（原始值）      --color-blue-500: #1677ff
  ↓ 别名
语义令牌（按用途）      --color-primary: var(--color-blue-500)
                         --color-danger: var(--color-red-500)
  ↓ 组件引用
组件令牌（组件内专用）   --button-bg: var(--color-primary)
```
- **全局令牌**：原始调色板，不含语义。
- **语义令牌**：按用途命名（primary/danger/success），改主题只改这一层。
- **组件令牌**：组件内部专用，隔离组件定制。

> 关键洞察：**业务代码只引用语义令牌，不引用原始值**。这样换主题（如暗色模式）只需重定义语义令牌，所有组件自动跟随。详见 [01-3 样式方案](../01-3-styling/README.md)。

### 2. CSS 变量 vs 预处理器变量
- **CSS 变量（自定义属性）**：运行时可改、能被 JS 动态读写、天然支持主题切换。**现代首选**。
- **Sass/Less 变量**：编译时替换、不能运行时改、做不了动态主题。
> 暗色模式本质是"运行时换一套变量值"，所以必须用 CSS 变量。

### 3. 主题化与暗色模式
```css
:root { --color-bg: #fff; --color-text: #000; }       /* 默认（亮色） */
[data-theme="dark"] { --color-bg: #1a1a1a; --color-text: #eee; }  /* 暗色 */

/* 业务代码只用语义令牌，不写死颜色 */
body { background: var(--color-bg); color: var(--color-text); }
```
切换主题只需改 `data-theme` 属性，所有令牌值整体切换。呼应 [01-3 样式](../01-3-styling/README.md) 与 [01-10 可访问性](../01-10-accessibility-multiplatform/README.md)（对比度）。

### 4. 组件库：设计系统的代码实现
基于令牌实现的标准化组件（Button/Input/Table…）。成熟方案有 Material UI、Ant Design 等；团队也可基于 Radix/headless UI + 自己的令牌搭私有组件库。组件库的 API 设计见 [组件 API 设计](./component-api.md)。

## 常见坑

- ❌ **业务代码硬编码颜色/间距**：`color: #1677ff`、`padding: 13px`——绕过了令牌，主题切换和一致性全失效。
  - ✅ 正例：只用令牌（`color: var(--color-primary)`）。
- ❌ **令牌层级缺失**：只有原始值没有语义层，换主题要改无数处。
- ❌ **设计系统停留在"组件库"**：有组件没规范，大家还是不知道什么时候用什么。
  - ✅ 正例：配套文档说明使用场景和禁忌。
- ❌ **过早建设计系统**：小项目强行搞完整设计系统，维护成本超过收益（违反 [YAGNI](../../00-foundation/tradeoffs.md)）。先从令牌开始，按需演进。
