# 键盘可达性（Keyboard Accessibility）

> 不是所有用户都用鼠标。键盘用户、屏幕阅读器用户靠 Tab 和方向键导航。如果界面只能鼠标操作，这部分用户就被排除在外。键盘可达性是 a11y 最基础也最常被忽视的一环。

## 是什么

键盘可达性指**所有功能都能用键盘完成**。核心是：元素能获得焦点、焦点可见、焦点顺序合理、键盘操作符合约定。

一句话边界：**拔掉鼠标，你的应用还能用吗？** 能——就是键盘可达。

> 这和 [01-8 焦点与键盘交互](../01-8-interaction-forms/focus-keyboard.md) 紧密相关——那里讲焦点管理的技术细节，这里讲 a11y 的整体要求。

## 为什么：谁需要键盘操作

| 用户 | 为什么依赖键盘 |
|---|---|
| 视障 + 屏幕阅读器 | 看不到鼠标位置，靠键盘 Tab 导航 |
| 运动障碍 | 无法精确操控鼠标，用键盘/开关设备 |
| 重复劳损（RSI）患者 | 鼠标引起疼痛，偏好键盘 |
| 效率用户 | 键盘比鼠标快（开发者、数据录入） |

键盘操作是 a11y 的"最大公约数"——做好它，屏幕阅读器、开关设备、效率用户都受益。

## 怎么用：四个要求

### 1. 元素能获得焦点
- 语义化交互元素（`<button>`/`<a>`/`<input>`）天然可聚焦。
- **div/span 默认不可聚焦**——用 div 做按钮是 a11y 重灾区。给 div 加 `tabindex="0"` 让它能聚焦，但还要补键盘处理（回车/空格触发）和 role。
- 详见 [01-8 tabindex](../01-8-interaction-forms/focus-keyboard.md)。

### 2. 焦点可见 ★
聚焦的元素要有**可见的焦点指示**（默认 outline 环），让键盘用户知道"现在焦点在哪"：
```
❌ *:focus { outline: none }   // 删焦点环，键盘用户彻底迷路（a11y 大忌）
✅ 保留 outline，或自定义更明显的焦点样式
```
> 删除焦点环是最常见也最致命的 a11y 问题。嫌默认丑可以自定义，但**不能没有**。

### 3. 焦点顺序合理
Tab 顺序应符合阅读顺序（通常 DOM 顺序）。避免：
- 用 `tabindex="1+"` 强制改 Tab 顺序——破坏 DOM 顺序，维护噩梦，也易让键盘用户困惑。
- 隐藏的元素仍在 Tab 序列（如 `display:none` 的内容应移出 Tab 流，但 `visibility:hidden` 仍可 Tab 到，是个坑）。

> 原则：**靠 DOM 顺序保证 Tab 顺序**，几乎不用正数 tabindex。

### 4. 键盘操作符合约定（WAI-ARIA Authoring Practices）
自定义交互组件要实现标准键盘行为：
| 组件 | 键盘约定 |
|---|---|
| 按钮 | 回车/空格激活 |
| 链接 | 回车跳转 |
| 模态框 | Esc 关闭、焦点锁在内 |
| 菜单 | 方向键移动、回车选中、Esc 关闭 |
| 标签页（Tabs） | 左右方向键切换 |
| 复选框 | 空格勾选 |
| 下拉 | 方向键展开选择 |

不做这些，键盘用户看到组件却无法操作。

### 跳过链接（Skip to content）
长页面的导航栏有几十个链接，键盘用户每次要 Tab 几十次才到正文。提供"跳到主内容"链接：
```
<a href="#main" class="skip-link">跳到主内容</a>   <!-- 通常视觉隐藏，Tab 时显现 -->
<main id="main">...</main>
```

## 常见坑

- ❌ **删焦点环**：键盘用户看不到焦点。
- ❌ **div 模拟按钮不补键盘**：键盘用户进不去/激活不了。
- ❌ **tabindex 正数**：破坏 Tab 顺序。
- ❌ **隐藏元素仍可 Tab**：用户 Tab 到"看不见"的元素，困惑。
