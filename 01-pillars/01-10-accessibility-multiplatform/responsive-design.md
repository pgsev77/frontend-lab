# 响应式设计（Responsive Design）

> 同一份应用，要从 320px 手机到 4K 显示器都能用。响应式设计是"一套代码适配所有屏幕"的策略层。CSS 手段见 [01-3 响应式样式演进](../01-3-styling/responsive-evolution.md)，这里讲整体策略。

## 是什么

响应式设计指**让界面根据屏幕尺寸/设备自适应**的设计方法。核心三要素：
1. **流式布局**（Flex/Grid + 弹性单位）
2. **媒体查询/容器查询**（按尺寸切换样式）
3. **响应式资源**（图片/字体按设备适配）

一句话边界：**响应式 = 一套代码，多端适配。** 对比"为每端做独立应用"，成本低、维护统一。

> 这呼应 [前端本质](../../00-foundation/frontend-essence.md) 差异 3——前端运行在屏幕尺寸不可控的环境，响应式是对抗这种不可控的核心策略。

## 为什么：为什么必须响应式

- **设备碎片化**：手机/平板/笔记本/桌面/折叠屏，尺寸千差万别。
- **用户分布**：移动流量已超 PC，不做移动适配等于放弃大半用户。
- **维护成本**：为每端单独开发，成本翻倍且易不一致。

响应式用**一套代码 + 自适应布局**，兼顾所有尺寸。

## 怎么用：整体策略

### 移动优先（Mobile First）★ 方法论
从最小屏幕开始设计，向上增强（详见 [01-3 响应式演进](../01-3-styling/responsive-evolution.md)）：
- 手机是约束最强的环境（小屏、弱网、触屏），先在它上做好，桌面增强就稳。
- CSS 用 `min-width` 向上增强（基础样式是手机，加媒体查询增强桌面）。
- 避免"桌面优先再裁剪"导致手机加载冗余。

### 断点基于内容，不基于设备
别写"iPhone 宽度 375px""iPad 宽度 768px"——设备无穷多。断点应设在**布局需要变化的临界点**：
```
/* 不是"在 iPad 上变两列"，而是"容器够宽就两列" */
```
配合 `auto-fit` + `minmax` 可实现无断点的自适应（[01-3 响应式演进](../01-3-styling/responsive-evolution.md)）。

### 触摸友好（移动适配）
不只是布局，交互也要适配触屏：
- **点击区域够大**：按钮至少 44×44px（Apple HIG）/ 48×48dp（Material），手指能准确点。
- **间距足够**：相邻可点击元素留间距，防误触。
- **避免 hover 依赖**：触屏没有 hover，关键操作不能只在 hover 显现。

### 响应式资源
```
<!-- 图片按屏幕和 DPR 提供不同尺寸 -->
<img srcset="photo-480.jpg 480w, photo-960.jpg 960w, photo-1920.jpg 1920w"
     sizes="(max-width: 600px) 100vw, 50vw"
     src="photo-960.jpg" />
<!-- 字体按设备子集化 -->
```
小屏下小图、大屏下大图、高清屏下高清图。呼应 [01-1 视口与坐标](../01-1-view-fundamentals/viewport-coordinates.md) 的 DPR。

### 容器查询：组件级响应式
组件不知道自己会被放多宽的地方。容器查询让组件按**自身容器**响应，比媒体查询（只看视口）更精准。详见 [01-3 现代布局](../01-3-styling/modern-layout.md)。

## 常见坑

- ❌ **桌面优先 + 裁剪**：默认桌面样式，手机加载冗余且易遗漏裁剪。
  - ✅ 正例：移动优先，向上增强。
- ❌ **断点按设备**：设备一更新断点就过时。按内容布局临界点。
- ❌ **只调布局不调交互**：响应式只改了排版，按钮还是鼠标大小，手机点不到。
- ❌ **忽视横屏**：手机横屏（短而宽）也是常见状态，要测。
