# 状态架构（State Architecture）

> 状态分类（[第 1 篇](./state-classification.md)）回答了"有哪些状态"，状态架构回答"这些状态该放在哪一层"。这是把状态管理从"能跑"提升到"好维护"的关键设计能力。

## 是什么

状态架构指**整个应用的状态分层与归属设计**——决定每个状态放在哪一层（组件局部 / 全局 store / URL / 服务端缓存 / 持久层），以及它们如何协作。

```
应用状态架构分层：
┌─────────────────────────────────┐
│ URL 状态（可分享/可刷新的）       │  ← 路由库
├─────────────────────────────────┤
│ 服务端状态（后端数据的缓存）       │  ← TanStack Query
├─────────────────────────────────┤
│ 全局客户端状态（跨组件共享的 UI）  │  ← Zustand/Context
├─────────────────────────────────┤
│ 局部组件状态（只本组件用）         │  ← useState
├─────────────────────────────────┤
│ 持久状态（跨刷新保留）             │  ← localStorage
└─────────────────────────────────┘
```

一句话边界：**好架构让每个状态归到最合适的层，不冗余、不越界。**

## 为什么：架构混乱的代价

没有状态架构的项目常见症状：
- **同一数据多处存储**：用户信息既在 store 又在 Context 又在组件 state，三处打架，不知谁是真理。
- **状态层级错配**：只一个组件用的状态被提到全局（过度设计）；或十个组件要共享的状态散落在各处（共享困难）。
- **跨层耦合**：组件直接读写 localStorage，绕过状态层，难以测试和替换。

好架构的核心原则是**单一数据源**：每份数据只有一个"权威来源"，其他都是它的派生或缓存。

## 怎么用：归属决策树

拿到一个状态，按这个顺序判断它的归属：

### 决策 1：能不能放进 URL？
如果它是"页面位置/视图状态"（当前路由、筛选、分页、排序、Tab），**优先放 URL**。理由：可分享、可刷新、可后退。详见 [01-7 路由](../01-7-routing/README.md)。

### 决策 2：是不是来自后端？
是 → 服务端状态层（Query 库），**绝不进 Redux**。详见 [01-6](../01-6-data-fetching/README.md)。

### 决策 3：跨多少组件共享？
- 只 1 个组件用 → **局部 state**（useState）。别提前全局化。
- 父子几层共享 → **状态提升**到共同祖先。
- 跨很远、不相关组件共享 → **全局 store**（Zustand）或 Context。

### 决策 4：要跨刷新保留吗？
要 → **持久层**（localStorage/IndexedDB），配合状态层同步。

### 状态提升 vs 下沉
- **提升（Lift up）**：多个组件要共享 → 把状态提到它们的共同祖先。提到哪一层？提到"需要它的最底层共同祖先"，不要过度提升到全局。
- **下沉**：只局部用的全局状态 → 拉回组件内部，减少全局污染。

> 判断标准：**状态的使用范围决定它的层级**。只两个相邻组件共享，提升到它们的父组件即可；整个应用要用的（主题、登录态），才放全局。

### 分层协作的典型模式
```
API 层（定义接口契约）→ Hook 层（用 Query 封装获取+缓存）→ 组件层（用 Hook）
     ↑ 这个分层让"数据从哪来""怎么缓存""怎么显示"各自独立，可测试可替换
```
API 层只管"怎么请求"，Hook 层管"缓存/竞态/重试"，组件只管"显示"。详见 [01-6 数据架构位置](../01-6-data-fetching/README.md) 和 [01-12 架构](../01-12-architecture-engineering/README.md)。

## 常见坑

- ❌ **同一数据多处存储**：用户信息在 store 和组件 state 各一份，更新不同步。
  - ✅ 正例：单一数据源，其他地方派生或订阅。
- ❌ **过度全局化**：一个弹窗开关放全局 store。只有真正跨组件共享才全局。
- ❌ **服务端状态进全局 store**：手动同步噩梦。呼应 [状态分类](./state-classification.md)。
- ❌ **直接读写 localStorage 绕过状态层**：难测试、难追踪。
  - ✅ 正例：用状态库 + 持久化中间件（如 Zustand persist），统一管理。
