# frontend-lab · 前端知识宇宙

> 一个**前端专精**的学习型工作空间。内容按"原理优先"生成，供系统阅读、建立完整的前端知识体系。
> 定位：从零到一、自顶向下与自底向上双向打通，精细到**原子概念**。

---

## 一、这是什么

`frontend-lab` 不是一个具体项目，而是一套**前端知识体系**。它把前端领域拆解成可独立阅读的知识单元，按层级组织，目标是：

- 看得见**全貌**（自顶向下：从前端本质 → 支柱 → 原子概念）
- 钻得下**根底**（自底向上：每个原子概念都能追溯到地基）
- 学得懂**原理**（不只记结论，更理解"为什么这样设计"）

## 二、心智模型：两条主轴

整个体系挂在两条主轴上。**任何前端知识点，都能在这两条轴上归位**——这是本工作空间最重要的认知锚点。

| 轴 | 核心问题 | 覆盖支柱 |
|---|---|---|
| **视图轴** | 界面怎么描述 · 怎么组织 · 怎么渲染 · 怎么不卡 | 01-1 视图基础、01-2 组件化、01-3 样式、01-4 渲染 |
| **状态轴** | 数据从哪来 · 怎么存 · 怎么变 · 怎么同步到视图 | 01-5 状态管理、01-6 数据获取、01-7 路由 |

**交互是两轴的交汇**：用户操作 → 改状态（状态轴）→ 状态变 → 视图更新（视图轴）→ 视图响应 → 用户。01-8 交互与表单落在这条交汇线上。

另外五个支柱是横切的：**01-9 性能与体验**优化两轴、**01-10 可访问性与多端**让两轴适配各种环境与人、**01-11 安全**守住两轴的边界、**01-12 架构与工程化**组织两轴的代码、**01-13 可观测性与质量**检验两轴的产出。

## 三、目录结构

```
frontend-lab/
├── README.md              ← 你在这里。工作空间总纲
│
├── 00-foundation/         ← 地基与心智：为什么前端长这样
├── 01-pillars/            ← 核心支柱：学习重心（13 个支柱）
├── 02-advanced/           ← 前端进阶：从单页到服务端渲染与大型应用
├── 03-engineering/        ← 工程实践：知识如何变成上线产品
└── 09-prerequisites/      ← 支撑基础：浏览器/网络/JS 等底层（按需查阅）
```

> **分层思想**：`00~03` 是**语言无关**的骨架；语言绑定层（`90-lang/`，具体框架/构建）作为独立模块补充，换技术栈只需替换它，骨架不变。

## 五、每个原子概念的结构

为保证"原理优先"和"双向打通"，每篇原子笔记遵循统一结构：

```
# [概念名]

## 是什么
一句话定义 + 精确边界。

## 为什么（原理推导）
为什么需要它、为什么这样设计。讲清权衡与来由，不直接抛结论。

## 怎么工作 / 怎么用
机制细节或使用方式。（代码示例用伪代码，暂不绑定具体语言。）

## 常见坑
实践中容易踩的错误。

## 关联（双向打通）
- 依赖 ↓：理解它之前需先懂 —— [原子概念链接]
- 属于 ↑：它在树中的位置 —— [主题/支柱链接]
- 相关 →：兄弟或交叉概念 —— [链接]
```

## 六、怎么读

### 推荐路径一：自顶向下（先建全局观）
1. 读 `00-foundation/`，建立前端世界观和两条主轴
2. 通读 `01-pillars/README.md`，扫一眼 13 个支柱的全貌
3. 选一个支柱，从它的 README 往下钻到原子概念
4. 遇到底层不懂，回 `09-prerequisites/` 查
5. 想看知识怎么落地成产品，去 `03-engineering/`

### 推荐路径二：自底向上（从问题出发）
1. 遇到一个具体概念（如"重渲染"），直接读它的原子笔记
2. 顺"依赖 ↓"往下钻，直到地基
3. 顺"属于 ↑"往上汇，看清它在全貌中的位置

### 推荐路径三：按主题深挖
直接挑感兴趣的支柱，按其 README 的顺序系统学完。
