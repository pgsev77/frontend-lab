# 00 · 地基与心智 (Mindset)

> 这一层不教具体技术，而是回答**"前端到底难在哪、为什么长这样"**。它是后面所有概念能挂靠的"为什么"的归处。建议首先通读。

## 本模块解决什么问题

前端有海量概念（组件、状态、虚拟 DOM、重渲染、SSR、Core Web Vitals……），如果只记"它是什么"，会学得很散。本模块给你一个**世界观**：理解前端的核心矛盾与权衡，后面每个概念都能在脑子里归位。

## 详细大纲（点击标题阅读）

### [00-0 前端的本质](./frontend-essence.md)
- 前端 vs 后端的根本差异（用户感知 · 数据投影 · 不可控环境 · 异步与用户行为 · 规模化组织）
- 前端是"用户体验的最前线"：为什么体验差=流失（不可"后端正确就行"）
- 前端工程哲学：体验优先 · 声明优先 · 防御性 · 可组合 · 性能感知

### [00-1 两条主轴 ★（心智锚点）](./two-axes.md)
- 视图轴：怎么描述 · 怎么组织 · 怎么渲染 · 怎么不卡
- 状态轴：从哪来 · 怎么存 · 怎么变 · 怎么同步到视图
- 交互是两轴的交汇：操作 → 状态 → 视图 → 响应
- 实战：用两轴给任意前端知识点归位（归位练习）

### [00-2 贯穿一切的权衡](./tradeoffs.md)
- 声明式 vs 命令式（可读性 vs 精细控制）
- 客户端状态 vs 服务端状态（谁才是真理）
- 体验 vs 性能（流畅感 vs 加载速度）
- 现在成本 vs 未来成本（技术债的本质）

### [00-3 复杂度从何而来](./complexity-sources.md)
- 状态与视图的同步难题（声明式 UI 的一致性维护）
- 异步带来的时间错位（数据没到、用户已点）
- 多端多形态（Web/移动/SSR，同一逻辑不同宿主）
- 规模化的视图与状态组织（组件/状态/样式在大型应用里不失控）
- 不可控环境（浏览器/设备/网络/屏幕都不可控）

### [00-4 一个需求的完整生命周期（9 步全景图）](./requirement-lifecycle.md)
> 这是 `03-engineering` 的预览，这里先给全貌，细节在 03。

1. 需求与设计澄清 → 2. 组件拆分与状态设计 → 3. 接口契约 → 4. 编码实现 → 5. 联调与测试 → 6. 设计与代码评审 → 7. 构建发布 → 8. 线上监控 → 9. 复盘与迭代

每步的核心产出与"如果跳过会怎样"。

## 学完本模块你应当能回答
- 前端和后端的本质区别是什么？这带来了哪些工程要求？
- 任意一个前端概念（如"虚拟 DOM"），它属于视图轴还是状态轴？解决什么问题？
- 前端复杂度主要来自哪里？
- 一个前端需求从接到上线，标准流程是哪几步？
